### 既有能力

插件与Chatflow共同实现来源引导改图、实际空间图技术审阅后继续、整套关联改号事务和纯计算机流程名称模式。该版本的真实验证状态以本轮具名报告为准；新代码不改变旧FAIL/UNKNOWN。

- `part_mark_mode=name_only`仅适用于无已知数字标号义务的纯计算机vector流程，稳定part ID保持；原响应可经有记录的生产适配推导模式，不自动补号。结构图仍执行编号合同。
- 参考准备使用受核原图区域和可选蒙版，绑定来源/底图/尺寸/批准身份；蒙版不保证模型区域外像素不变。source与母图同时存在时必须明确选择并留记录。
- 图像保存后，实际底图的逐项技术审阅未通过则停止依赖图与整套提升。`Workspace.review_visibility`、`approve_reference_preparation`、`approve_image_annotations`与原嵌字ROI批准均是操作员Python入口，未作为模型/普通工具动作开放。所有批准绑定实际hash，不能由图单中的reviewed字样授予。
- 关联改号使用私有已审锚点，冻结图形底图，所有相关图/说明/索引准备完成后一次提升当前版本；未完成修订、局部成果和最近完整版本分开显示。
- provider_rejected及UNKNOWN保留，不通过新run_id清零。私有policy可包含一次性`recovery_authorizations`；只对原明确拒绝记录及具名恢复证据开放新attempt，UNKNOWN不得借此重发。支持材料默认unsent。
- 上传后用“预览”读取来源；“规划”才会请求自然规划。Loop在needs_source、待图像审阅、待修改批准、拒绝或UNKNOWN处停止；未达到条件时不执行下游图件。

版本 **0.3.8（受控修复候选）**。Dify 专利附图插件，含持久图集工作区、原图修改补充、单图生成/修改及图集导出。直连 OpenAI 官方 API，图像模型固定 `gpt-image-2.6-flare`，规划/文字与视觉辅助使用 `gpt-6.1-sol`。

历史v0.1.3的R4单图复测仍有关键错误，原结论保留。v0.2.0改为成套附图合同，原生安装和本轮测试状态以对应交付报告为准；内容审阅与文件校验分别记录。

## 工作区与受控部署（沿用并扩展v0.3.4）

当前为工程候选。每个包以内容UID、签名SHA及运行文件清单区分；不能把版本号相同的不同候选当成同一个已实测包。原始失败、UNKNOWN及旧候选均保留。

- 已有附图时先保留原图并规划修改/补充，无附图时按技术类型建立新图集；“机电结构”保留机械、电气两类。
- “查看来源”仅预览上传材料；“规划”在操作员开启模型后会调用文字模型。“确认图单”“执行单图”支持逐图核对；“生成”会循环执行。
- 原嵌字改号必须由操作员核对实际底图SHA与白色ROI；没有经核锚点的空间图不得假称关联修改完成。未完成修订可“查看已完成”；“导出”保留最近完整版本。
- 用量投影保留有效计数及cache_write_tokens，未知字段另记不完整，缺失不当0。HTTP拒绝、结果未知与已保存但不可用分别留证，失败占槽，不自动重试。

本机SDK无可信app_id；工作区模型执行使用独立worker/实例、数据库和存储。必须同时配置PATENT_DRAWING_ALLOW_MODELS=1、PATENT_DRAWING_ISOLATED_WORKER=1、PATENT_DRAWING_OPERATOR_POLICY绝对私有路径，且policy.enabled=true。public app_id、plan_json或模型输出不能授予权限。

私有policy的schema为patent-run-policy-1，含run_id、enabled、ledger_root和limits.image/text；null表示无固定调用次数上限，仍记录每次实际派发、请求与响应。有限image上限还需操作员自己的整组图单估算清单。不得换run_id或清账本重置一次已发请求。未配置私有policy的旧单图工具保留原接口行为；受控部署必须提供policy，不能仅凭普通工具参数宣称隔离。

v0.3.8开启policy时还必须提供私有`continuity`：`registry_path`为账本目录外的绝对SQLite路径，`ledger_id`为固定64位十六进制身份，`mode`为`initialize`、`resume`、`adopt_existing`或`migrate`。`initialize`只显式建立全新任务账本，不能用于重置旧数据库；已有旧版账本先关闭调用，再以`adopt_existing`及完整旧DB的`previous_db_sha256`核验接续。移动账本须使用`migrate`、相同registry/identity、旧DB SHA和完整一致副本。原路径在迁移后不能继续派发；缺DB/注册表、历史计数回退、缺旧lineage均停止。注册表与账本及所有原始请求/响应一并备份，不通过删除其中一个恢复执行。

四角支承可见性、接口几何、图文一致和缩小可读性均须检查实际输出；文件可打开、代码回归及规则提示不能代替专利专业接受或申请就绪。结束测试时关闭私有模型门，保留独立存储及账本。

## 已实现的专利绘图辅助

- 结构示意图、流程图、模块框图、电路图四种模板，要求白底黑线、清晰标号与引出线，避免装饰效果。
- 接收给定部件标号表和保留约束；提示模型不补造未提供的零件、尺寸、连接和步骤，不自行重编号。
- 改图接收一张原图和一段指令，可附透明 PNG 蒙版限定修改区域，并要求保留未涉及的结构、标号和位置。
- 生成输出 PNG 或原生静态 SVG；修改输出 PNG。先输出 Dify 标准文件，再输出不含图片base64的精简JSON。
- 本地校验图片完整性、方向、容量、蒙版与SVG静态内容；保留文件／提示模板／输入hash、官方request ID和usage（缺失时为null）。

这些模板是绘图辅助约束，不能保证模型不会产生几何、文字、标号、连接或修改外溢错误。每次输出均标记 `requires_human_review=true`、`professional_review_status=not_reviewed`。`file_validation_passed=true`仅表示文件可接受，不代表专业质量或申请就绪。尚未接入具名专业规则包，不承诺CAD精度或跨调用多视图一致性。

## 安装和凭据

1. 在 Dify 插件页面选择从本地文件安装 `oasisintwrite_patent_drawing-0.3.8.signed.difypkg`。该包为本地构建包；安装签名策略由你的Dify管理员处理，插件不自动修改服务器安全设置。
2. 在该插件的授权设置中填写 **OpenAI API密钥**。只做本地字段检查，保存成功不表示模型权限、余额或真实调用已验证。插件不会读取开发机的 `.env.local`，密钥不在安装包内。
3. 工作流添加“生成专利附图”或“修改专利附图”工具节点，将输出 `files` 接到 Answer 节点或后续文件处理节点。

需要项目具备 OpenAI 官方模型访问权限及可用额度。不存在第三方代理base_url或静默模型回退。

### Dify 文件来源配置

处理 Dify `file` 输入时，SDK通常提供签名URL。请配置凭据中的可选项：

| 配置 | 用途 |
| --- | --- |
| 可信Dify文件origin | 文件URL的准确协议、主机和端口，例如 `https://dify.example.com`。URL形式参考图／蒙版必填，只接收该origin的签名 `/files/<uuid>/file-preview` 或 `/files/tools/<uuid>.<png|jpg|jpeg|webp>` 路径。 |
| Dify内部抓取基址 | 可选，例如 `http://api:5001`，解决容器不能访问本机公网地址的情况。仅对已匹配可信origin的签名预览URL进行内部地址重写。 |

地址中不能包含凭据、子路径、查询串或片段。下载不跟随重定向、不附带OpenAI密钥。插件不接受任意公网图片URL，也不直接访问会隐式下载的SDK `File.blob` 属性。字节／data URL形式输入仍会做同样的图片校验。

## 工具参数

| 参数 | 说明／默认 |
| --- | --- |
| `prompt` | 必填绘图说明或修改指令；与下两项合计最多24000字符 |
| `reference_labels` | 可选，逐行填写标号与部件名称 |
| `constraints` | 可选，必须保留的关系、视角和位置等 |
| `drawing_type` | `structure`／`flowchart`／`block_diagram`／`circuit`，默认structure |
| `size` | `auto`／`1024x1024`／`1536x1024`／`1024x1536`；生成默认1024x1536，修改默认auto |
| `quality` | low／medium／high，默认high |
| `complexity` | low／medium／high；生成默认medium，修改默认low |
| `output_format` | 生成可选png／svg，默认png；修改固定png |
| `reference_image` | 修改必填：一张PNG／JPEG／WebP，最多10MiB、1600万像素；方向归一化并转PNG后仍需满足容量限制 |
| `mask` | 修改可选：严格小于4MiB的PNG；与方向归一化后的参考图同尺寸，必须含完全透明像素，透明区域表示允许修改 |

每次一张图。输出尺寸为像素尺寸，不能以改写DPI或文件扩展名替代实际分辨率。`auto`不保证修改后像素尺寸与原图相同；蒙版也不能保证区域外逐像素不变。

### 生成示例

`drawing_type=structure`，`output_format=png`：

```text
prompt：绘制结构示意图。矩形壳体中只有一根水平转轴，转轴左右两端各穿出壳体一小段。只绘制壳体轮廓和转轴，不增加内部零件。
reference_labels：
1：壳体
2：转轴
constraints：保持转轴水平；标号1和2各出现一次，引出线分别指向壳体和转轴。
```

### 修改示例

上传原图至 `reference_image`：

```text
prompt：只将标号2和对应引出线移至转轴右端外侧，避免遮挡轮廓。
reference_labels：
1：壳体
2：转轴
constraints：保持壳体、转轴轮廓、连接关系和标号1的位置不变，不新增零件。
```

### SVG边界

SVG仅用于生成；官方编辑接口不接受SVG作为栅格输入，也不支持SVG输出。插件不会自动转换、再次调用模型或回退PNG。SVG须通过静态标签／属性白名单，禁止脚本、实体、外部样式／引用、事件、嵌入栅格等；不兼容的SVG会明确失败。SVG按文件交付，Dify前端是否内联展示取决于实际版本。

## 错误和费用

API连接超时20秒、读取超时300秒，请求与读取调用另有300秒绝对截止；Dify文件下载全程截止60秒。截止使用Dify SDK的gevent协作运行时，覆盖连接、响应头、首块、块间和EOF；到期取消请求，响应／客户端清理各自限时0.1秒并在独立greenlet执行，不延长调用方等待。正常结束也复核截止，不声称抢占任意不协作的CPU代码。生成／修改POST不自动重试。超时、断网和5xx返回结果未知，应先核对OpenAI用量；不能推断未执行或未收费。错误不回显上游原始响应、客户内容或密钥；SDK公开invoke的前置文件转换错误也会安全包装。参数、参考图和蒙版校验在生图请求前完成。

输出上限15MiB／1600万像素，SVG另限2MiB；API响应最多24MiB。插件内存声明512MiB。usage缺失时为null，不按token补造账单；SVG author usage与图像usage分别保留。

### 0.2.0 图组工具

- `patent_drawing_set_validate`：校验 `drawing-set-1` 计划及上一版本，返回拓扑执行队列、受影响图号、未覆盖关系。仅进行结构校验。
- `patent_drawing_set_render`：执行一张图。复杂结构调用固定的 OpenAI 官方图像模型；逻辑流程与已确定几何使用受限图元渲染 SVG/PNG，不调用图像模型。关联修改须同时绑定图号、原PNG及其SHA256；派生图须绑定声明的依赖。
- `patent_drawing_set_package`：按规格与实际PNG哈希校验全套，交付A4 PDF和ZIP。ZIP附PNG、确定性SVG、计划、图目、标号表、来源/未知项和审阅状态。缺图、串图、旧规格或错误文件拒绝打包。

一组支持1至24图；主Chatflow每轮最多8张图像模型图。PDF为栅格图件排版，SVG保留确定性图形的矢量版本；SVG中文显示依赖查看器字体，PNG/PDF使用随包的Noto Sans SC（OFL许可见_assets）。图元和关系检查不能证明技术方案完整或专利附图合规，最终均标为待人工审阅。

配套 `patent_drawing_set_chatflow-0.2.0.yml` 支持“规划：材料”“生成：材料”“生成”“修改：改动”“导出”“重置”。技术材料使用粘贴文本；图片上传用于原图引用过期后的补传，需填写图号且通过原始SHA校验。PDF原件应先提取文本，当前对话流未接入PDF自动提取。高级计划导入用于经审阅的图组执行，须明确区别于自动规划。

完整图组仅在打包成功后提交为当前版本；中途失败保留上一套完整图组和当前工作进度，不自动重复付费请求。会话仅保留最近24版索引，原消息与图件未删除。重新启动生成会建立新图组；修改沿用同一材料和相邻版本。跨会话引用不继承。Dify签名URL过期后必须补传相同字节的原PNG，不能用重编码图片替换；多张失效引用可先重新导出下载并按图补传，批量引用刷新尚不支持。

`patent_drawing_set_plan` 是规划请求传输工具：规划规则和材料仍由Chatflow编排，工具使用同一provider凭据向官方 `/v1/responses` 发送一次请求（固定文本模型gpt-6.1-sol，JSON模式，store=false）。不启用其他Dify模型供应商，不修改全局模型密钥或开关；拒绝、未完成或无效JSON不进入图像生成。JSON模式不保证图组合同正确，必须经后续严格校验；高级审阅计划导入与自动规划测试分别记录。
# v0.3.0 工程候选：图文来源与附图工作区

本版实施P0—P4。有原图时根据交底修改补充，无原图时按技术类型规划新图集。原文件、页图、未知项和历史版本分别保留；扫描或不明确的图形不自动判为无图。

模型执行默认关闭。仅由运营方在后续模型、资料和调用预算获准后设置`PATENT_DRAWING_ALLOW_MODELS=1`；用户JSON/预算参数不能开启。原图复用和工程测试不证明自然语言制图、空间图技术保真或专业接受。

持久化须部署在实际共享持久卷：本实例已核plugin_daemon的`/app/storage`挂载，默认私有根为`/app/storage/patent-drawing-v3`，运营方可设置`PATENT_DRAWING_STATE_ROOT`。SQLite在同卷跨进程唯一派发并占用预算；响应先保存再封装，UNKNOWN不自动重发。SDK租户/plugin KV命名空间加运行用户、系统会话ID隔离数据。进程临时目录和分离磁盘多主机不属于已验证部署。

容量：总输入16MiB、最多6文件/12源页/20MP页渲染；最多24视图/80MP解码/48MiB图组PNG。超限拒绝，不截断原件。PDFium在限时/限资源独立进程解析；pypdfium2==5.14.0及原wheel许可证随部署安装；中文OFL字体随包。
